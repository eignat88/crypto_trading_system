## Правила актуализации

- Не фиксировать вручную количество тестов: источником истины служат discovery и CI.
- Различать «код компонента реализован» и «операционный gate пройден».
- Не отмечать paper/live готовыми без соответствующих acceptance gates.
- Не добавлять performance sealed holdout до разрешённой даты и проверки выборки.
- При изменении DDL обновлять канонические миграции и migration-runner tests.
